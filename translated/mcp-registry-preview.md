# MCP 注册表发布介绍 | 模型上下文协议（MCP）博客

今天，我们正式发布模型上下文协议（MCP）注册表——一个面向公开可用 MCP 服务器的开放目录和 API，旨在提升其可发现性与实现便利性。通过标准化服务器的分发与发现方式，我们在扩大其覆盖范围的同时，也让客户端更容易接入。

MCP 注册表现已进入预览阶段。开始使用：

- 按照我们的《向 MCP 注册表添加服务器》指南添加你的服务器（面向服务器维护者）
- 按照我们的《访问 MCP 注册表数据》指南获取服务器数据（面向客户端维护者）

# MCP 服务器的唯一事实来源 #

2025 年 3 月，我们曾表示希望为 MCP 生态构建一个中心化注册表。今天，我们正式宣布 https://registry.modelcontextprotocol.io 已作为官方 MCP 注册表上线。作为 MCP 项目的一部分，MCP 注册表及其上层 OpenAPI 规范均为开源——允许任何人构建兼容的子注册表。

我们的目标是标准化服务器的分发与发现方式，为子注册表提供一个可供构建的主要事实来源。反过来，这将扩大服务器的覆盖范围，并帮助客户端在整个 MCP 生态中更轻松地找到服务器。

## 公共与私有子注册表 #

在构建中心化注册表时，对我们来说重要的是不去取代社区和公司已经建立的现有注册表。MCP 注册表作为公开可用 MCP 服务器的主要事实来源，各组织可以选择基于自定义标准创建子注册表。例如：

公共子注册表（例如与各个 MCP 客户端相关联、带有特定立场的“MCP 市场”）可以自由地扩充和增强它们从上游 MCP 注册表获取的数据。每类 MCP 终端用户都有不同的需求，而如何以带有特定立场的方式恰当地服务其终端用户，则取决于各个 MCP 客户端市场。

私有子注册表将存在于对隐私和安全有严格要求的企业内部，但 MCP 注册表为这些企业提供了一个可供构建的统一上游数据源。至少，我们的目标是与这些私有实现共享 API 模式，以便相关的 SDK 和工具能够在整个生态中共享。

在两种情况下，MCP 注册表都是起点——它是 MCP 服务器维护者发布和维护其自行申报信息的中心化位置，供这些下游消费者加工整理并交付给终端用户。

## 社区驱动的审核机制 #

MCP 注册表是一个由注册表工作组维护、采用宽松许可证的官方 MCP 项目。社区成员可以提交 issue 来举报违反 MCP 审核指南的服务器——例如包含垃圾信息、恶意代码或冒名顶替合法服务的服务器。随后，注册表维护者可以将这些条目列入拒绝名单，并追溯性地将其从公共访问中移除。

# 开始使用 #

开始使用：

- 按照我们的《向 MCP 注册表添加服务器》指南添加你的服务器（面向服务器维护者）
- 按照我们的《访问 MCP 注册表数据》指南获取服务器数据（面向客户端维护者）

MCP 注册表的本次预览旨在帮助我们在正式发布（GA）之前改进用户体验，并且不提供数据持久性保证或其他担保。我们建议 MCP 采用者密切关注开发进展，因为在注册表正式发布之前可能会发生破坏性变更。

在我们持续开发注册表的过程中，我们鼓励大家在 modelcontextprotocol/registry GitHub 仓库上提供反馈和贡献：讨论（Discussion）、Issue 和拉取请求（PR）一律欢迎。
