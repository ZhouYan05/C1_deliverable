# 拿来说明 03：83 条术语表（glossary.csv）是怎么借助 AI 定下来的

> 本文档说明：`pipeline/glossary.csv` 的构建过程——32 篇英文原文中高频术语的
> 抽取、定译与争议裁决，含原文、prompt、产出与对比。

---

## 一、决策背景

挑战验收要求「术语表 ≥ 50 条且全文一致」。31 篇文章跨越 LLM 基础、智能体、
MCP、安全、代码评审五大主题，同一个词在 31 篇里出现几百次。若不在翻译前
锁定译法，机器翻译必然漂移——"agent" 可能翻成 智能体/代理/AI 助手/机器人，
"context" 可能翻成 上下文/语境/背景，读者跨篇阅读时直接精神分裂。

术语表不是「翻译完再归纳」，而是「翻译前先冻结」，然后**注入到每篇翻译的
系统提示词里**。这是本次管线与普通机翻的根本区别。

## 二、原文（AI 的输入，从 32 篇原文中筛出的候选词样本）

```
高频候选（部分）：
Vibe Coding / Scaffolding / Context Engineering / Context Rot /
Agent / Agentic / Coding Agent / Tool Use / Function Calling /
Multi-agent System / Orchestration / Guardrails / Grounding /
Hallucination / Prompt Injection / Jailbreak / SAST / DAST /
Observability / On-call / MCP / RAG / PRD / SDK / CLI / IDE …
```

## 三、我给 AI 的 prompt（原样）

```
从这批 CS146S 课程原文中提取需要统一译法的术语，输出 CSV（category,en,zh,note）：
- category 分为：基础概念 / 智能体 / 协议与工具 / 安全 / 工程实践；
- 译法原则：优先技术社区通用译法；社区未约定俗成的，采用「中文（English）」
  首现加注策略；
- 难点词必须给出定译理由写进 note，例如：
  Vibe Coding、Scaffolding、Context Rot、Agentic 这几个词争议最大，
  请给出你的定译和理由；
- 目标是 ≥50 条且全文一致，宁缺毋滥，不要收录一次性出现的普通名词。
```

## 四、AI 产出（节选，含难点词裁决）

```csv
category,en,zh,note
基础概念,Vibe Coding,氛围编程（Vibe Coding）,本课程主题：用自然语言"凭感觉"驱动 AI 生成代码的开发范式
智能体,Scaffolding,脚手架,围绕模型搭建的支撑性代码/流程
基础概念,Context Rot,上下文腐化,上下文变长后模型表现退化的现象
智能体,Agentic,智能体式,具备自主规划与行动能力
安全,Prompt Injection,提示注入,通过输入操纵模型行为的攻击
安全,SAST,静态应用安全测试（SAST）,Static Application Security Testing
…
```

AI 对四个争议词给出了完整裁决理由（节选）：

- **Vibe Coding → 氛围编程**：社区尚无公认译名，直译「氛围编码」偏口语，
  取「氛围编程」并强制保留英文原名，避免读者对不上原课名；
- **Scaffolding → 脚手架**：脚手架已是从前端工程界引入的成熟译法，
  本课程语境（围绕模型的支撑代码）完全贴合；
- **Context Rot → 上下文腐化**：「腐化」比「腐烂/衰减」更能体现
  "逐渐变质不可逆"的过程义；
- **Agentic → 智能体式**：区别于 Agent（智能体）名词本身，
  形容词统一用「智能体式」避免与「自主/自治」混淆。

最终产出 **83 条**，超出验收线 33 条，全部带分类与备注。

## 五、对比与评价

| 维度 | 无术语表机翻 | 术语表先冻结 + 注入 |
|---|---|---|
| 同一词译法数 | 3～5 种（实测常见） | 1 种 ✅ |
| 跨篇一致性 | 无保证 | 系统提示词强制 ✅ |
| 争议词 | 随机漂移 | 有裁决理由，可追溯 ✅ |
| 换课复用 | 不可用 | 换 glossary.csv 即可 ✅ |
| 验收达标 | 不稳定 | 83 条 ≥ 50 条 ✅ |

**实测佐证**：`spotcheck.py` 抽检时按「原文出现术语 → 译文是否含统一译名」
逐篇比对，83 条术语的译名在已发布 19 篇译文中全部命中，零漂移。

**结论**：术语表的价值不在「表」而在「先于翻译冻结 + 注入提示词」这两个动作。
AI 在这里的贡献是难点词的裁决推理——给出理由而非拍脑袋，让译法决策
可审、可辩、可复现。
